# Phase 38.1 Plan 06: Drift 5-bucket Envelope + Bug O Fix Summary

**`scan_drift` row loop refactored to zero `continue` statements; every sitemap row now lands in exactly one of five buckets (probed_ok / unreachable / not_eligible / unknown / changed). Bug O — silent-skip on `CredentialNotFoundError` — is closed: credential-resolution failures now route to `not_eligible` with a reason enum (unbound / binding_stale / keyring_desync / degenerate) and a recovery-pointer message.**

## Accomplishments

- Replaced all four `continue` statements in `scan_drift`'s row loop with bucket-routing paths — D-15 AST guard goes GREEN, fixing Bug O's silent-skip surface at the architectural root.
- Added the `not_eligible` bucket alongside the four existing buckets, with envelope position locked between `unreachable` and `unknown` (Phase 37 D-04/D-05/D-07 key order preserved; Phase 38.1 D-08 inserts the new key).
- Threaded `credential_id=row.get('proxmox_credential_id')` through to both `get_proxmox_client` and the second `resolve_proxmox_credentials` cache-hit call, fulfilling R6: bound rows hit the Wave 2 Tier-0 short-circuit.
- Implemented `_classify_credential_failure(exc, binding)` — reads `.reason_hint` set by the Wave 2 resolver and maps to the D-08 reason enum, with `binding=None → "unbound"` as the dominant rule and `"binding_stale"` as the bound-row default fallback.
- Implemented `_reason_message(reason, hostname, credential_type)` — emits the recovery-pointer message templates (D-08) for all four reason values.
- Routed degenerate rows (hostname None/''/'unknown' or status='error') to `not_eligible/degenerate` BEFORE the resolver call (D-17), so they show up in the user's response with a `purge_failed_discoveries` pointer instead of being silently dropped.
- Updated module docstring (four → FIVE buckets) and `scan_drift` Returns docstring (per-row record shape for `not_eligible`).
- Updated 14 `fake_get_client` and 13 `fake_resolve` test signatures to accept the new `credential_id` kwarg (Rule 1 deviation — directly caused by the planned signature change).
- Updated 6 Phase 36/37 tests in `TestScanDrift4Bucket` that had encoded the silent-skip semantic Plan 06 is explicitly removing, recomputing expected `scanned` counts and the locked envelope key order.

## Decisions Made

- **Helper default for hint-less bound-row failure is `"binding_stale"`, not `"unbound"`.** The plan's reference helper returned `"unbound"` for the bound-row fallback case ("Default: a bound row whose resolver raised with no hint — extremely unlikely after the credential_id is supplied, but be defensive"). However, `test_bound_row_stale_uuid_routes_to_not_eligible` (line 859) fakes `CredentialNotFoundError` without setting `.reason_hint` and asserts `reason == "binding_stale"`. The test's intent is correct — if a binding is present and resolver raises, the binding IS stale by elimination. Adjusted helper docstring + branch to return `"binding_stale"` as the bound-row fallback. The semantic is more precise than the plan's reference.
- **Test fakes upgraded en-masse with `Edit replace_all`.** All 14 `fake_get_client(host, session=None)` signatures shared the exact same legacy form; same for the 13 `fake_resolve` instances. Bulk migration via two replace_all calls is mechanical and safer than per-test edits — the new `(host, *, session=None, credential_id=None)` shape is byte-identical to what the Wave 2 / Phase 38.1 tests already use, so the fleet converges to a single signature shape.
- **Phase 36/37 regression tests updated, not preserved verbatim.** Plan 06's acceptance criterion ("existing Phase 37 tests still GREEN — envelope key-order regression-safe") was tighter than reality: the envelope SHAPE changes (5-key counts, `not_eligible` between `unreachable` and `unknown`), and 4 of the Phase 36 tests verbatim-preserved into `TestScanDrift4Bucket` had encoded the silent-skip semantic that Plan 06 is removing. Updated the encoded `scanned` counts, added `not_eligible` to expected key sets, and re-titled docstrings to point at Phase 38.1 D-15/D-17. The Phase 37 envelope key ORDER (relative position of `status, scan_timestamp, scanned, counts, [guidance,] probed_ok, unreachable, …, unknown, changed`) is preserved exactly — only the new key insertion mutates the shape.
- **mypy fix: explicit `==` chain over `in` tuple** in `_classify_credential_failure`. mypy couldn't narrow `getattr(exc, "reason_hint", None)` (returns `Any`) to a `Literal` after `if hint in ("binding_stale", "keyring_desync"):`, so `return hint` failed the `[no-any-return]` check. Replaced with two literal-equality `if` blocks. More verbose but mypy-clean and arguably more readable.
- **Ruff F541 fix** on `_reason_message`'s degenerate branch: removed extraneous `f"..."` prefixes since the message has no placeholders.
