## Fixed Issues

### CR-01: Destructive Phase 38.1 migration runs on every fresh install — drops a table init_schema just created and prints alarming banner

**Files modified:** `src/homelab_mcp/migration.py`
**Commit:** 7bc3230
**Applied fix:** Added defense-in-depth gating in both SQLite (`run_sqlite_migrations`) and Postgres (`run_postgres_migrations`) destructive blocks. The gate inspects the live `devices` table for the binding columns: when no table exists (fresh install) the block is skipped and only the version stamp is written; when both binding columns are already present (state-file deletion on a fully-migrated DB) the block is also skipped. Only a genuinely-pre-existing devices table without binding columns triggers the drop+recreate path. This prevents (a) wasted drop-and-recreate of a just-created table on every fresh install, (b) silent data loss when `migration_state.json` is deleted on a live DB, and (c) test-suite banner spam on `:memory:` SQLite databases (also resolves WR-06).

### CR-02: Postgres destructive migration banner lies — DROP TABLE CASCADE does NOT clear discovery_history rows

**Files modified:** `src/homelab_mcp/migration.py`
**Commit:** 7bc3230
**Applied fix:** Postgres path now executes `DELETE FROM discovery_history` BEFORE `DROP TABLE devices CASCADE`, mirroring the SQLite path. CASCADE only drops the FK constraint, not dependent rows. Also guarded the DELETE on table existence using `information_schema.tables` (defense-in-depth — also resolves WR-09 for Postgres).

### CR-03: `_cmd_credentials_remove` per-node path silently leaks keyring secret for legacy/buggy cluster entries with non-empty hostname

**Files modified:** `src/homelab_mcp/server.py`
**Commit:** 6508df6
**Applied fix:** The per-node `entries` filter now also requires `e.get("scope", "node") == "node"`. Cluster entries with non-empty hostname (legacy or hand-edited) are now skipped in the per-node remove path, preventing the silent keyring orphan.

### CR-04: Tier-0 resolver short-circuits when env-var credentials are set, silently ignoring sitemap binding

**Files modified:** `src/homelab_mcp/proxmox_api.py`
**Commit:** d11686d
**Applied fix:** Restructured the auth-precedence check in `get_proxmox_client`: when `credential_id` is supplied AND explicit/env-var auth is also present, log a `logger.warning` so operators can detect the override. The env-var path still wins (preserving SC-5 back-compat) but the conflict is now visible in logs. Drift's `not_eligible` routing remains correct because the resolver-call path is unchanged when no explicit auth is present.

### WR-02: SQLite `bulk_null_credential_binding` will hit SQLite's max-parameters limit on large rotations

**Files modified:** `src/homelab_mcp/database.py`
**Commit:** f1b450d
**Applied fix:** Replaced the single `IN (?,?,...)` clause with a chunked loop (chunk_size=500) inside `SQLiteAdapter.bulk_null_credential_binding`. The 500-batch cap stays safely under the default `SQLITE_MAX_VARIABLE_NUMBER` of 999 on older SQLite builds while leaving headroom for the trailing `updated_at` parameter on the UPDATE. The aggregated `affected_hostnames` list is returned exactly as before.

### WR-03: `_archive_registry_for_phase_38_1` returns synthetic `.bak.none` path that doesn't exist — banner misleads

**Commit:** 7bc3230

### WR-04: Drift's second `resolve_proxmox_credentials` call on success duplicates Tier-0/Tier-1/Tier-2 logic

**Files modified:** `src/homelab_mcp/proxmox_api.py`, `src/homelab_mcp/drift_detection.py`
**Commit:** 28236e3
**Applied fix:** Added a process-lifetime `_RESOLUTION_TELEMETRY_CACHE: dict[(host, credential_id), (scope, cluster_name)]` in `proxmox_api.py`, populated from EVERY successful tier (Tier-0 UUID, Tier-1 per-node, Tier-2 cluster cache hit, Tier-2 cluster walk). Exposed `get_resolution_telemetry()` helper. `drift_detection.scan_drift` now consults the cache first and only falls back to a fresh `resolve_proxmox_credentials` call when cold (defensive). On flaky keyring backends, this prevents mis-routing reachable hosts into `not_eligible/keyring_desync`.

### WR-05: `find_devices_by_hostname_or_ip` Postgres implementation may mismatch `INET` rows stored with CIDR notation

**Files modified:** `src/homelab_mcp/database.py`
**Commit:** 0ec0e5a
**Applied fix:** Changed the WHERE clause from `connection_ip::text = %s` to `host(connection_ip) = %s` in `PostgreSQLAdapter.find_devices_by_hostname_or_ip`. `host()` strips any netmask suffix so a row inserted as `192.168.1.5/24` still matches a bare-IP query. The SELECT clause keeps `connection_ip::text AS connection_ip` for output stability (consumers expect plain-string IPs).

### WR-07: `_cmd_credentials_add` cluster path discards the returned `credential_id`

### WR-09: Phase 38.1 R10 migration runs `DELETE FROM discovery_history` without checking the table exists

Defense-in-depth against a future refactor that moves migration before init_schema.
