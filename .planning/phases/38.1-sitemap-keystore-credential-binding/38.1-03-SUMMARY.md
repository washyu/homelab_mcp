# Plan 38.1-03 Summary — Devices schema + adapter binding methods

## What was built

`devices` table on both SQLite and Postgres adapters now carries the two
nullable `ssh_credential_id` / `proxmox_credential_id` TEXT columns. Three
typed adapter methods (`set_device_credential_binding`,
`find_devices_by_hostname_or_ip`, `bulk_null_credential_binding`) encapsulate
all `?` vs `%s` placeholder differences inside the adapters — Plan 07's
`server.py` consumers never see raw SQL placeholders (Blocker B2 mitigated).
Both `get_all_devices()` flatten paths emit `eligibility: {ssh: bool, proxmox: bool}`
derived from the binding columns.
