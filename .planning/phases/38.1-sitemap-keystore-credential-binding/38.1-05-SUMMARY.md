## Decisions Made

- **Module-level import of `find_credential_by_id` on both resolver modules.** Plan ratified the lazy-import option for proxmox; switched to module-level for both because the test scaffolds already patched via the resolver-module namespace (`homelab_mcp.proxmox_api.find_credential_by_id`). Module-level is also the analog of `list_credentials` and `get_credential` (already module-level imports) — consistent surface for monkeypatching, no circular-import risk because the dependency direction is `proxmox_api → credential_store` and `ssh_tools → credential_store` (no reverse edge).
- **Variable rename `cluster_name → entry_cluster_name` in tier-0** of `resolve_proxmox_credentials` to dodge a mypy false-positive `unreachable` warning. mypy was narrowing the *later* tier-2 `cluster_name = entry.get("cluster_name", "")` based on tier-0 reassignment-shadowing semantics. Renaming the tier-0 local broke the narrowing chain. Functionally identical; cosmetic.
- **`scope_str` plain-str + `scope_literal` re-narrow at return.** Same mypy-friendliness pattern. tier-0 computes `scope_str = "cluster" if entry.get("scope") == "cluster" else "node"` then re-asserts the Literal at the return site. Could have used `cast(Literal[...], scope_str)` instead — chose explicit ternary for readability.
- **`SSHCredentials.hostname = hostname` (caller arg, not entry).** D-13 says UUID wins for the lookup; for the *returned* dataclass, preserving the caller's hostname maintains downstream log/error context. The connection still uses the registry entry's username, but the hostname field stays as the caller passed it (matches existing return semantics in tier-1/tier-2 where the function is hostname-keyed).
