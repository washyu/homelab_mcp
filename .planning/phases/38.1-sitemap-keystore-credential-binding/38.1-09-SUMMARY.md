## Decisions Made

1. **Worktree base correction at agent start.** The worktree's HEAD was `b580d309` (a stale snapshot from a prior attempt or a merge artifact); the orchestrator-supplied expected base was `0e15d95b`. Hard-reset the worktree to the expected base before any work — without this, the integration test would have run against a Plan-08-incomplete tree and behaved differently.

2. **Module-alias double-patch.** Discovery: `homelab_mcp.server` and `src.homelab_mcp.server` are TWO separate sys.modules objects in this repo's package layout, despite backing the same .py file. Verified with `python -c "import homelab_mcp.server as a; import src.homelab_mcp.server as b; print(a is b)"` returning False. Every monkeypatch.setattr that targets a module attribute must therefore patch BOTH aliases. The first attempt patched only `homelab_mcp.server.set_device_credential_binding` and failed because `_cmd_credentials_add` (loaded from `src.homelab_mcp.server`) read the un-patched alias's binding.

3. **Wrapper-seam thin-lambda replacement.** The server-module wrappers `get_sitemap_rows_for_hostname`, `set_device_credential_binding`, and `null_bindings_for_credential_id` lazy-import `NetworkSiteMap` inside the function body and instantiate `NetworkSiteMap()` with no arguments — which lands on the user's `~/.mcp/sitemap.db`. Patching `NetworkSiteMap` directly would require the test to know how the wrapper's internal instantiation flows, brittle. Replacing the wrappers themselves with thin lambdas that close over the test's adapter is the single clean seam: the API contract (the wrapper signature) is preserved; the I/O is redirected.

4. **Pre-stamp the Phase 38.1 R10 destructive migration.** Without the pre-stamp, `SQLiteAdapter().init_schema()` would invoke `run_sqlite_migrations` which would attempt to back up the registry (creating an unwanted `.bak.<timestamp>` file in tmp_path) and drop the freshly-created `devices` table. Idempotency check (`_phase_38_1_applied()`) only returns True AFTER a successful first run, so without the pre-stamp the migration always fires on the test's fresh DB. Writing the stamp file before init_schema is the simplest fix.

5. **Field names for argparse.Namespace in Test 5.** The plan's reference snippet had `type, host, username, scope, cluster, auth_type`. Reading `server.py:1170-1206` showed the actual argparse `dest` values are `hostname, username, credential_type, key_path, scope`. The plan explicitly invited this fix ("If the executor finds the field names differ from the snippet above, fix the test to match the actual handler"). Used the actual field names; Test 5 passes.

6. **Test 5's stdin.isatty() forced to False.** The auto-bind helper has TTY-vs-non-TTY branching: TTY prompts; non-TTY skips with a warning. For Test 5 the row has no existing binding, so the non-TTY path's "skip with warning" branch doesn't fire (it only fires for the existing-binding case). Forcing `sys.stdin.isatty() == False` keeps the test deterministic regardless of the executor's TTY state.
