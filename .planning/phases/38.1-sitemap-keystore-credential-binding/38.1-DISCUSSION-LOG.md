## Auto-bind ambiguity policy

(Captured in initial session — checkpoint preserved seven question/answer pairs.)

### Q1 — Canonical workflow + no-match behavior

**User's choice:** Workflow is `credentials add` → `discover_and_map` → `scan_infrastructure_drift`. No matching sitemap row at `add` time is the EXPECTED state — silent (no error, no warning, just `Stored ... credential for ...`).

**Notes:** User-driven principle. Captured as D-01.

### Q2 — Identity scheme: keep `hostname` as natural key, or rename?

| Option | Description | Selected |
|--------|-------------|----------|
| Keep hostname (Recommended) | Natural-key field stays `hostname`; SSH+Proxmox overlap handled by separate `credential_type` keying | ✓ |
| Add optional --name display label | Additive; no schema rewrite | |
| Rename hostname to name (architectural shift) | Decouple from network identity | |

**User's choice:** Keep hostname. Friendly-name rename deferred to v1.8 backlog.

### Q3 — Credential `hostname` field: IP vs hostname semantics

| Option | Description | Selected |
|--------|-------------|----------|
| Keep SPEC behavior (Recommended) | Accept any string (IP, short name, FQDN) as opaque label; auto-bind matches hostname OR connection_ip | ✓ |
| Hostname-only matching (drop OR clause) | Strict semantics | |
| Reject IPs in credentials add | Validation at registration | |

**User's choice:** SPEC behavior. Multi-match is rare (sitemap-side data quality issue) and handled by interactive prompt.

### Q4 — Single-match WITH existing non-null binding (overwrite case): UX

**User's choice:** Interactive prompt using hostname only — no UUIDs in user-facing text. Prompt: `Sitemap row "<hostname>" is already bound to a different <type> credential. Overwrite the mapping? [y/N]:`. Non-TTY → skip the bind, print warning, exit 0. Credential is still stored regardless.

### Q5 — Non-TTY behavior on overwrite/multi-match prompt

| Option | Description | Selected |
|--------|-------------|----------|
| Skip the bind, print warning, exit 0 (Recommended) | Default-safe; no surprise rebinds in unattended scripts | ✓ |
| Always overwrite when non-interactive | Risky — silent data mutation | |
| Add a --force flag; without it, skip | Explicit opt-in | |

### Q6 — Multi-match (>1 sitemap row matches): UX

| Option | Description | Selected |
|--------|-------------|----------|
| Interactive prompt with hostname choices (Recommended) | Numbered list, hostnames only, [s] skip | ✓ |
| Skip + warn listing hostnames | Less interactive | |
| Hostname-exact wins over connection_ip silently | Implicit precedence | |

**User's choice:** Interactive prompt with hostname choices. Non-TTY → skip + warn.

### Q7 — Cluster-scope `credentials add --scope cluster:<name>`: auto-bind behavior

| Option | Description | Selected |
|--------|-------------|----------|
| Skip auto-bind for cluster-scope (Recommended) | Cluster credentials remain unbound at row level; resolver Tier-2 cluster walk handles them at scan time | ✓ |
| Auto-bind by probing each sitemap row | Heavyweight at `add` time | |
| Skip + offer separate `credentials sync` command | Deferred to backlog | |

## `not_eligible` shape + sitemap eligibility field

(Captured in initial session — checkpoint preserved three question/answer pairs.)

### Q1 — `not_eligible[].reason` vocabulary

| Option | Description | Selected |
|--------|-------------|----------|
| Small enum + message (Recommended) | Codes: `unbound`, `keyring_desync`, `binding_stale`; companion `message` field for human sentence | ✓ |
| Free-form reason string only | Unparseable | |
| Enum only, no message | Less actionable | |

**User's choice:** Enum + message. (Note: extended in AST area to add `degenerate` — see D-08, D-17 in CONTEXT.md.)

### Q2 — Cluster-served rows: how does drift handle them?

**User's choice:** Drift attempts cluster walk; lands in `probed_ok`/`unreachable` normally (NOT `not_eligible`). Hard failure → `not_eligible` with `reason="unbound"`. SPEC acceptance criterion needs revision: `counts.not_eligible == COUNT(*) WHERE proxmox_credential_id IS NULL AND no cluster credential resolves the row`. `eligibility.proxmox` on `get_network_sitemap` reflects binding-state only.

| Bool pair per SPEC (Recommended) | `{ssh: bool, proxmox: bool}` | ✓ |
| Object per type with bound + bound_to_user | More info, more shape | |

## Resolver `credential_id` mismatch behavior

### Q1 — UUID-miss behavior (stale binding)

| Option | Description | Selected |
|--------|-------------|----------|
| Raise CredentialNotFoundError, never fall back (Recommended) | Hard error; drift routes to `not_eligible` with `reason="binding_stale"` | ✓ |
| Fall back silently to hostname-exact-match | Re-introduces the silent-skip bug class | |
| New BindingStaleError exception | Class explosion; reason enum already encodes this | |

**User's choice:** Hard error, no fallback. Captured as D-11.

### Q2 — Keyring-miss after UUID hit (desync)

| Option | Description | Selected |
|--------|-------------|----------|
| Raise CredentialNotFoundError with desync warning, drift routes to keyring_desync (Recommended) | Same exception type; drift differentiates via context | ✓ |
| Return a sentinel value (None) | Breaks Phase 34 "tier-1 raises on hard fail" contract | |
| Distinct KeyringDesyncError exception | Most precise; class explosion | |

**User's choice:** Same exception, drift differentiates. Captured as D-12.

### Q3 — `credential_id` + `host` mismatch

| Option | Description | Selected |
|--------|-------------|----------|
| Don't care — UUID wins, ignore host (Recommended) | The whole point of the binding | ✓ |
| Warn but proceed | Noisy on every drift scan | |
| Validate host matches entry.hostname OR connection_ip | Wasted work; breaks cluster walks | |

**User's choice:** UUID wins. Captured as D-13.

### Q4 — Parameter shape on the two resolvers

| Option | Description | Selected |
|--------|-------------|----------|
| Keyword-only, default None — both resolvers (Recommended) | Per SPEC constraint; matches `session=` precedent | ✓ |
| New top-level `resolve_by_credential_id()` function | Doubles API surface; forces caller branching | |

**User's choice:** Keyword-only param. Captured as D-14.

## AST guard pattern for `no silent skip`

### Q1 — Guard shape

| Option | Description | Selected |
|--------|-------------|----------|
| Forbid every `continue` inside the row-loop body (Recommended) | AST walks for-loop body of `scan_infrastructure_drift`, flags any `Continue` node | ✓ |
| Forbid `except <Exception>: continue` patterns specifically | Narrower; misses `if cond: continue` | |
| Allowlist a single named guard variable | Brittle; ties source style to test | |
| Combine forbid-continue AST guard + functional regression test | Belt-and-suspenders | |

**User's choice:** Forbid every `continue`. Captured as D-15.

### Q2 — Guard scope

| Option | Description | Selected |
|--------|-------------|----------|
| Only `scan_infrastructure_drift` for now (Recommended) | Matches Phase 35 D-15's targeted shape | ✓ |
| Every function in `drift_detection.py` | Future-proof but over-broad | |

**User's choice:** Only the one function. Captured as D-16.

### Q3 — Existing degenerate-row filter at lines 142-143

| Option | Description | Selected |

| Move filter outside the loop | Clean alternative; loses per-row visibility | |

**User's choice:** Convert to bucket routing — extends `not_eligible.reason` enum from 3 to 4 codes. Captured as D-17 with refinement of D-08.

### Q4 — Functional regression test alongside AST guard?

## Migration banner + ordering

### Q1 — Migration trigger

| Option | Description | Selected |
|--------|-------------|----------|
| Startup migration with version-stamp guard (Recommended) | Idempotent; matches `run_sqlite_migrations` pattern | ✓ |
| Explicit CLI command (`homelab-mcp migrate-v17`) | Manual; safer but easier to skip | |
| Startup + env var first-run gate | Loud; high friction | |

**User's choice:** Startup-fired with version stamp. Captured as D-19.

### Q2 — Order of operations

| Option | Description | Selected |
|--------|-------------|----------|
| Backup registry → drop devices → stamp version (Recommended) | Stash-then-mutate-then-mark; preserves registry data first | ✓ |
| Drop devices → backup registry → stamp | Reverse; no technical reason | |
| Single transaction-equivalent block with rollback | Hard across SQLite + JSON file | |

**User's choice:** Backup → drop → stamp. Captured as D-20.

### Q3 — User-visible banner shape

| Option | Description | Selected |
|--------|-------------|----------|
| Multi-line stderr banner with recovery steps inline (Recommended) | Three blocks: what, why, copy-paste commands; matches v1.6 ssh_credentials drop banner | ✓ |
| Single-line summary + URL pointer | Terse; easier to miss | |
| MCP log-notification + stderr summary | Surfaced in client; impl cost — runs before MCP session up | |

**User's choice:** Multi-line stderr banner. Captured as D-21.

### Q4 — `.bak.<timestamp>` already exists

| Option | Description | Selected |
|--------|-------------|----------|
| Always use a fresh timestamp; never overwrite (Recommended) | Disk litter is small; preserves audit trail | ✓ |
| Refuse to migrate if any .bak.<ts> exists | Forces manual cleanup | |

**User's choice:** Fresh timestamp always. Captured as D-22.
