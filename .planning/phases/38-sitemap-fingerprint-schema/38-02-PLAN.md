```python
def test_run_sqlite_migrations_adds_fingerprint_column_idempotently_phase38(tmp_path):
    """Phase 38 D-08 / SC-3: ADD COLUMN fingerprint is idempotent and non-destructive."""
    import sqlite3
    from homelab_mcp.migration import run_sqlite_migrations

    db_path = str(tmp_path / "legacy.db")
    # Build a pre-Phase-38 schema (with usb/pci/block but no fingerprint).
    conn = sqlite3.connect(db_path)
    conn.execute("""
        CREATE TABLE devices (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            hostname TEXT NOT NULL,
            connection_ip TEXT NOT NULL,
            last_seen TEXT NOT NULL,
            status TEXT NOT NULL,
            usb_devices TEXT,
            pci_devices TEXT,
            block_devices TEXT
        )
    """)
    # Insert a legacy row to confirm it survives the migration with NULL fingerprint
    conn.execute(
        "INSERT INTO devices (hostname, connection_ip, last_seen, status) VALUES (?, ?, ?, ?)",
        ("legacy.local", "10.0.0.1", "2026-04-01T00:00:00", "success"),
    )
    conn.commit()
    conn.close()

    applied1 = run_sqlite_migrations(db_path=db_path)
    assert "add_column_fingerprint" in applied1, applied1

    # Verify column exists, legacy row still present, fingerprint is NULL.
    conn = sqlite3.connect(db_path)
    cols = {row[1] for row in conn.execute("PRAGMA table_info(devices)").fetchall()}
    assert "fingerprint" in cols, cols
    row = conn.execute(
        "SELECT hostname, fingerprint FROM devices WHERE hostname = ?",
        ("legacy.local",),
    ).fetchone()
    assert row is not None
    assert row[0] == "legacy.local"
    assert row[1] is None  # NULL on legacy rows — re-discovery populates
    conn.close()

    # Re-run is idempotent — no add_column_fingerprint on second call.
    applied2 = run_sqlite_migrations(db_path=db_path)
    assert "add_column_fingerprint" not in applied2, applied2
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Discovery payload → parse_discovery_output | JSON from remote SSH host (already trusted via SSH credentials) is deserialized and stored. |
| SQLite ALTER TABLE | DDL runs against the user's local database file. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-38-02-01 | Tampering | parse_discovery_output(fingerprint) | mitigate | The parser does `json.dumps(discovery_data["fingerprint"])` — Python's json.dumps is the trust boundary. Any payload Python rejects (e.g., circular references) raises TypeError before the value reaches the DB. The remote host already has SSH-authenticated trust; this is defense-in-depth, not the primary control. |
| T-38-02-02 | Denial of Service | Oversized fingerprint payload | accept | A misbehaving probe could return a many-MB stdout. The dpkg-fingerprint probe always reduces to 64 hex chars (sha256sum on the remote). os-release is bounded to a few hundred bytes by /etc/os-release format. uname is single-line. Worst-case storage footprint is ~1KB per device row. Acceptable. |
| T-38-02-03 | Tampering | ALTER TABLE on user DB | mitigate | The migration is idempotent (PRAGMA check before ALTER) and uses a static column literal `ADD COLUMN fingerprint TEXT` — no parameter interpolation, no SQL injection vector. The `# noqa: S608` annotation acknowledges the static-string rule per Phase 35 D-09c convention. |
| T-38-02-04 | Information Disclosure | Legacy rows | accept | Old rows get NULL fingerprint until re-discovery. NULL is the correct semantic — no information leaked, no stale value confused for current. SC-3 explicitly accepts this. |
| T-38-02-05 | Tampering | Schema-rebuild branch | mitigate | Pre-Phase-35 DBs upgrading through Phase 38 hit the schema-rebuild path; D-08b ensures the new fingerprint column is in BOTH the CREATE TABLE devices_new block AND the target_cols list. Verified by the schema-rebuild test (separate test_run_sqlite_migrations_schema_rebuild already exercises this branch — manual check required during execution). |
</threat_model>
