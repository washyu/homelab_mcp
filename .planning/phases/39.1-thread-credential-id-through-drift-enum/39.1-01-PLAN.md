<design_decision>
**Option B selected — hostname→credential_id side-map passed as a new parameter to `_enumerate_proxmox_vms`.**

The key design question: how does `_enum_one` recover `credential_id` for each host? Two options were evaluated:

- **Option A:** Add `proxmox_credential_id` to the `probed_ok` record shape at line 941. _Rejected_ — breaks the locked 7-key contract enforced by `tests/test_drift_detection.py:699 test_per_row_record_shape_preserved_for_probed_ok`. That test exists specifically to LOCK the shape; mutating it has documentation cost and extends the surface area of `probed_ok` records to all consumers (drift response JSON, MCP tool callers, future filter logic).

- **Option B (selected):** Build a `host_to_binding: dict[str, str | None]` map at the call site in `scan_drift` and pass it as an extra arg to `_enumerate_proxmox_vms`. Side-map only lives long enough to be consumed. Source-of-truth is the SAME `row.get("proxmox_credential_id")` read at line 718 — no new credential-resolution logic, no new state. Cluster-dedupe behavior preserved: the dedupe at line 415 picks one (hostname, cluster_name) pair per cluster; the side-map is keyed by hostname, so whichever hostname survives the dedupe finds its binding (or `None` for cluster-served rows where binding is NULL — at which point `get_proxmox_client(credential_id=None)` falls through to Tier-1/Tier-2 cluster walk, matching the row-loop's existing semantics at line 744-752).

Rationale: Option B preserves the locked record-shape contract, contains the side-map's lifetime to a single function call, and reuses the existing source-of-truth pattern. The "extra parameter on the helper" cost is trivial and clearly named.

**Cluster-dedupe correctness:** `_enumerate_proxmox_vms` dedupes by `(cluster_name OR hostname)` at line 415, so the surviving (hostname, cluster_name) pair is the representative for that cluster. The side-map MUST contain a binding for whichever representative-hostname survives. Since the side-map is built from the SAME `probed_ok` records that feed `_enumerate_proxmox_vms` (it's keyed on hostname taken from `record.get("hostname")`), this is automatic — every probed_ok record's hostname is in the map, so whichever hostname wins the dedupe has its binding available. For cluster-served rows where `proxmox_credential_id` is NULL, the map value is `None`, and `get_proxmox_client(host=h, session=session, credential_id=None)` falls through to the Tier-1/Tier-2 cluster walk — exactly the same fallback semantics as the row-loop's binding-NULL case at lines 744-752.
</design_decision>
