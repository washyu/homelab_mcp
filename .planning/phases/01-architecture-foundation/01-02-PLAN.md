<task type="auto">
  <name>Task 1: Rewrite server.py with MCP SDK lowlevel.Server</name>
  <files>src/homelab_mcp/server.py</files>
  <action>
Replace the entire HomelabMCPServer class with MCP SDK lowlevel.Server setup:

1. Create a module-level `server = Server("homelab-mcp", version="0.2.0", lifespan=app_lifespan)` instance.

2. Implement `app_lifespan` as an async context manager:
   - Load MCPConfig from config.py
   - Create ResourceManager(config), call initialize()
   - yield {"resource_manager": resource_manager}
   - In finally: await resource_manager.shutdown()

3. Register `@server.list_tools()` handler:
   - Call get_all_tool_schemas() to get all tool definitions
   - Convert each to types.Tool(name=name, description=schema["description"], inputSchema=schema["inputSchema"])
   - Return list of Tool objects

4. Register `@server.call_tool()` handler:
   - Receive name: str, arguments: dict | None
   - Get ResourceManager from server.request_context.lifespan_context["resource_manager"]
   - Call get_tool_handler(name) to get handler function
   - Call handler(arguments or {}) -- handlers still return {"content": [{"type": "text", "text": "..."}]}
   - Convert result to list of types.TextContent/ImageContent objects (adapter pattern from RESEARCH.md)
   - If handler raises ValueError (unknown tool), raise that to SDK (it will format the error)
   - If handler raises other exceptions, let SDK handle error formatting

5. Store a module-level reference to ResourceManager during lifespan for handlers that need direct access (set in lifespan, cleared on shutdown). This avoids every handler needing to pass through request_context.

6. Remove the old HomelabMCPServer class entirely. Remove hand-rolled JSON-RPC parsing, _success_response, _error_response, handle_request, the old run_stdio, and run_http methods.

7. Keep any utility functions that are still needed. Export `server` and the ResourceManager accessor.

Do NOT use FastMCP -- use lowlevel.Server per CONTEXT.md decision (the "decorator-based" intent is satisfied by @server.call_tool() and @server.list_tools() decorators).
  </action>
