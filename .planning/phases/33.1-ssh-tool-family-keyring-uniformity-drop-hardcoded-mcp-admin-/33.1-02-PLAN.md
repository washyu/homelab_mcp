<objective>
Clean the JSON tool schemas so the MCP protocol boundary never advertises `password` as a valid input property and never advertises `mcp_admin` as a default username. Implements D-01, D-02, D-03, D-12 from `33.1-CONTEXT.md`.

Purpose: Phase 33 D-06 ("passwords never enter chat") is currently violated by three schema entries that still list `password` as a property and two that still set `"default": "mcp_admin"` on `username`. This plan closes the schema surface, independently of Plan 03's tool deletions (so even if Plan 03 slips, the password surface is gone). Also fixes the "Defaults to mcp_admin if omitted" copy string flagged in CONTEXT D-12.

Output: Two modified schema files; MCP client sees fewer properties on 3 tools; no default username advertised.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client → server schema (`tools/list` response) | Agent reads the schema to know what params to pass; dropping `password` closes a write surface |
| Protocol boundary (`tools/call` with args) | Server validates args against schema; removing `password` means a caller that still sends password gets a framework-level schema-rejection, which is the desired D-06 enforcement |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33.1-05 | Information Disclosure | Schema still advertises `password` → agent sends plaintext password in chat | mitigate | Delete `password` property from `discover_and_map`, `bulk_discover_and_map.targets[]`, and `update_mcp_admin_groups`. Post-change, schema-aware clients won't offer password as a field. Agents that try to send one will be rejected by JSON schema validation at the MCP framework boundary. |
| T-33.1-06 | Tampering | In-flight caller relied on `password` schema param → silently drops to auth failure after removal | accept | Verified in CONTEXT: "any in-flight caller passing password silently drops to auth failure" — this is the Phase 33 D-06 principle working as intended. Error messages from `resolve_ssh_credentials` already point the caller to `homelab-mcp credentials add`. Low severity; transient during the deploy window. |
| T-33.1-07 | Tampering | Schema `default: mcp_admin` was read by old agents → they auto-send `username=mcp_admin` even when keyring has a different user | mitigate | Delete the `default` from schemas in D-03. Agents reading the new schema don't auto-fill a username; the resolver's new registry-scan (Plan 01) handles the empty case. |
| T-33.1-08 | Denial of Service | Partial schema change → schema/annotation parity CI test fails | accept | Not a threat — parity failure would block merge. This plan doesn't touch annotations or handler dispatch, so parity is preserved. |

Residual risk: **low**. Schema-only changes with TDD coverage on every edit.
