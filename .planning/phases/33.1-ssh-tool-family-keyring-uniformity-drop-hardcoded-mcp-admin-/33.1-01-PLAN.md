<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP tool input → resolve_ssh_credentials | Untrusted `hostname` string reaches registry enumeration; multi-user match produces error message listing registered usernames |
| credential_store.list_credentials → resolver | JSON hostname registry contents are effectively trusted (server-local file) but their contents surface into error messages |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33.1-01 | Information Disclosure | `resolve_ssh_credentials` ambiguous-match error message | accept | The error message names registered usernames. This is intentional (D-04a "agent can make a call to list keyring and get the username itself"). Registry contents are already exposed via `list_registered_servers` / `list_keyring_credentials` MCP tools — the resolver error re-surfaces the same information at the same trust level. No PII beyond hostnames and SSH usernames. |
| T-33.1-02 | Tampering | Registry file on disk | accept | Server trusts its own on-disk JSON registry (single-user homelab deployment model, Phase 33 D-06 scope). Threat rejected from scope per Phase 33. |
| T-33.1-03 | Denial of Service | Large registry → slow resolver | accept | `list_credentials()` returns a list; multi-user enumeration is O(n) in registered hosts. Homelab scope (tens of hosts max), not a DoS vector. |
| T-33.1-04 | Elevation of Privilege | Caller bypasses username with None to get a different user's credential | mitigate | Single-match branch: server picks the sole registered user for the hostname — that IS the user the caller implicitly authorized (they registered it). Multi-match branch: hard error, server never auto-picks. Zero-match branch: unchanged CredentialNotFoundError. No silent fallback to a different user. |

Residual risk: **low**. The disposition matches Phase 33's D-06 threat model for the keyring registry surface.
</threat_model>
