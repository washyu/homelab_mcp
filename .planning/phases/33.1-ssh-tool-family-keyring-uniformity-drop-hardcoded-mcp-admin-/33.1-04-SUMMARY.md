## Decisions Made

- **Four tests, not three** — added the bulk-propagation test (see Deviations §1) because D-06 and D-07 live in distinct code paths. Three tests covered D-06's call site + signature + end-to-end; the bulk path would have been uncovered by direct unit test (end-to-end test goes through `discover_and_store`, not `bulk_discover_and_store`). Four targeted tests ≈ same resolution, stricter net.
- **Monkeypatch on the `ssh_tools` module, not `sitemap`** — matches the pattern already used by the pre-existing `test_discover_and_store` test (line 281: `@patch("src.homelab_mcp.ssh_tools.ssh_discover_system")`). `sitemap.py` lazy-imports `ssh_discover_system` inside the function body (line 327: `from .ssh_tools import ssh_discover_system`), so the name resolves against `src.homelab_mcp.ssh_tools` at call time. Monkeypatching on `ssh_tools` works cleanly.
- **End-to-end test uses `ssh_connect` as the boundary, not `asyncssh.connect`** — `ssh_connect` is the correct abstraction layer (TOFU wrapper). It's imported at module load in `ssh_tools.py` (line 15), so `monkeypatch.setattr(ssh_tools_mod, "ssh_connect", fake_ssh_connect)` replaces the module-level attribute and the full stack threads through the fake.
- **Reused benign `exit_status=1` stdout=`""` from `conn.run()`** — `ssh_discover_system` calls `conn.run(...)` for many commands and inspects `.exit_status` / `.stdout`. Using a benign non-zero exit status short-circuits the discovery body without demanding a realistic shape from every shell command. The test only cares about the auth-boundary kwargs captured at `ssh_connect`, not the discovery output.
- **Cosmetic `mcp_admin` cleanup in docstring/comment** — see Deviations §2. Zero-reference state for the file matches Phase 33 D-13's intent and leaves future grep-based audits clean.
