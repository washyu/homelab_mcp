# Phase 33.1: SSH Tool Family Keyring Uniformity - Context

**Gathered:** 2026-04-22
**Status:** Ready for planning

<domain>
## Phase Boundary

Finish the Phase 33 keyring-only migration across the remaining SSH tool surface. After this phase:
- No source file has `username="mcp_admin"` as a function-parameter default or a JSON-schema default.
- No MCP tool schema exposes a `password` property anywhere (top-level or nested bulk-target items).
- The `mcp_admin`-specific MCP tools (`update_mcp_admin_groups`, `verify_mcp_admin_access`) are removed from the tool surface — Phase 33's D-18 made that account non-privileged, so tools that operate only on it are vestigial.
- A caller that provides only `hostname` resolves both `username` and `password` from the keyring registry; ambiguous registry state returns an actionable error pointing the agent to `list_keyring_credentials` / `list_registered_servers`.

Scope anchor: the Phase 33 live-testing gap recorded 2026-04-21 in ROADMAP.md.

Out of scope: new SSH credentials features, cluster-scoped Proxmox tokens (Phase 34), sitemap/discovery reliability bugs (Phase 35), MCP tool CRUD for registered servers (backlog 999.1).

</domain>

<decisions>
## Implementation Decisions

### Schema `password` Field Audit (D-06 enforcement)

- **D-01:** Remove the `password` property from `tool_schemas/network_tools_schema.py` `discover_and_map.inputSchema.properties` (line 17). Remove the `password` property from the nested `bulk_discover_and_map.targets[].properties` (line 48). Keyring becomes the only password source at the MCP protocol boundary for these tools.
- **D-02:** Remove the `password` property from `tool_schemas/ssh_tools_schema.py` `update_mcp_admin_groups.inputSchema.properties` (lines 131–134) — superseded by D-05 (the whole tool is removed), but listed explicitly so a partial revert of D-05 can't re-expose the password surface.

### Username Resolution When Omitted

- **D-03:** Remove `"default": "mcp_admin"` from the schema `username` property on both `discover_and_map` (line 15) and `bulk_discover_and_map.targets[]` (line 47). `username` remains optional in the schema (only `hostname` required). No default string is advertised to the agent.
- **D-04 (resolver contract):** When a caller provides only `hostname` and `username` is `None`, `resolve_ssh_credentials()` performs a registry scan by hostname:
  - **Single registered user** → inject both `username` and `password` from the keyring entry. This is the friendly one-entry path.
  - **Multiple registered users** → raise `CredentialNotFoundError` (or a new `AmbiguousCredentialError`) with a message naming the registered usernames and pointing the agent to `list_keyring_credentials` / `list_registered_servers` so it can retry with an explicit username.
  - **Zero registered users** → raise `CredentialNotFoundError` pointing at `credentials add <hostname> <username>` (existing message shape from D-05 in Phase 33).
- **D-04a:** The user's explicit model (verbatim): "the keyring entry is hostname and username then uses password entry for the password in the CLI so we inject the username and password from the keyring entry. Also I think the agent can make a call to list keyrings and get the username itself if needed." Drives D-04. Agent-side self-disambiguation is intentional — the server never picks between multiple registered users.

### `mcp_admin`-Specific Tool Removal

- **D-05:** Remove **both** `update_mcp_admin_groups` AND `verify_mcp_admin_access` from the MCP tool surface in lock-step. Same lock-step removal pattern Phase 33 used for `setup_mcp_admin` (D-10) / `update_server_credentials` (D-20) / `remove_server` (D-21):
  - `tool_schemas/ssh_tools_schema.py` — delete both schema entries.
  - `tool_handlers/ssh_handlers.py` — delete both handler functions (`handle_update_mcp_admin_groups`, `handle_verify_mcp_admin_access`).
  - `tool_handlers/__init__.py` — delete dispatch entries.
  - `tool_annotations.py` — delete annotation entries.
  - `openapi_app.py` — remove both tool names from any allow-lists.
  - `ssh_tools.py` — delete `update_mcp_admin_groups()` function and `verify_mcp_admin_access()` function and any helpers used only by them. Keep `_sudo_run` (still used by other paths).
- **D-05a (rationale, verbatim from user):** "we should drop this as we are also removing the need for the mcp_admin since again username comes from the keyring so a user doesn't need to create or use the mcp_admin." Phase 33's D-18 already made `mcp_admin` non-privileged — any sudo-capable registered user works. Tools whose name and internal logic are hardcoded to the literal `mcp_admin` account no longer have a reason to exist.
- **D-05b:** `connect_to_device` prompt — Phase 33 D-13 ended with "Step 6: Call `verify_mcp_admin` with `hostname="<hostname>"` — confirm sudo/admin access." Step 6 changes. New Step 6: call `ssh_execute_command(hostname=..., command="sudo -n true")` (or equivalent generic sudo check). The prompt no longer names a `*_mcp_admin` tool. Regression guard D-09 covers this.
- **D-05c:** MCP clients see two fewer tools at `tools/list` (down from whatever Phase 33 left — total is schema/annotation parity-gated, so CI will confirm). The quality-gate test from v1.2 (schema/annotation parity enforced, 56/56 tools at last count) must still pass after the removals — if parity breaks, that's intentional safety catching an incomplete removal.

### `sitemap.py` Default Cleanup

- **D-06:** In `src/homelab_mcp/sitemap.py`, change `discover_and_store` signature (line 312–319) — `username: str = "mcp_admin"` becomes `username: str | None = None`. Pass `username` straight through to `ssh_discover_system`, which already routes through `resolve_ssh_credentials()` per Phase 33.
- **D-07:** In the same file, `bulk_discover_and_store` (line 343–371) — change `target.get("username", "mcp_admin")` (line 357) to `target.get("username")`. Same propagation path as D-06.
- **D-07a:** No other sitemap.py edits needed. `discover_and_store` is the only discovery entry point downstream of the bulk path.

### Regression Guards (extend D-15/D-25 AST meta-test from Phase 33)

- **D-08:** Extend the Phase 33 AST meta-test to walk function `ast.arg.annotation` / `ast.FunctionDef.args.defaults` trees across `src/homelab_mcp/**/*.py` (excluding `tests/`) and fail if any parameter named `username` has a default of the literal `"mcp_admin"`. Catches reintroduction of D-06.
- **D-09:** Add a TOOLS-dict meta-test: walk all `TOOLS` / `NETWORK_TOOLS` / `SSH_TOOLS` / similar registry dicts at import time, recursively traverse `inputSchema.properties` at any nesting depth (including `items.properties` for array items), and:
  - Fail if any schema property named `username` has `"default": "mcp_admin"`.
  - Fail if any schema has a property named `password` at any nesting depth.
  Catches reintroduction of D-01, D-02, D-03 in one pass. Permanent D-06 protocol-boundary enforcement.
- **D-10:** Existing Phase 33 D-15/D-25 forbidden-strings meta-test gets the removed tool names appended: `update_mcp_admin_groups`, `verify_mcp_admin_access` (outside tests). Catches D-05 regression.
- **D-11:** Positive test for D-04 resolver behavior: monkeypatch registry to return two users for one hostname; assert `resolve_ssh_credentials(hostname="h", username=None)` raises an error whose message names both usernames AND mentions `list_keyring_credentials` (or `list_registered_servers`). Single-match and zero-match cases already covered by Phase 33 D-16/D-17 — extend with ambiguous case.

### Docstring Sweep

- **D-12:** Scope is narrow — fix known misleading copy flagged in scout:
  - `tool_schemas/network_tools_schema.py` line 14 description — "Defaults to 'mcp_admin' if omitted" → remove that clause; keep the "auto-injected from keyring" sentence that's already there.
  - `tool_schemas/network_tools_schema.py` line 19 description on the `password` field — moot, field is removed by D-01.
  - `tool_schemas/ssh_tools_schema.py` `update_mcp_admin_groups` description (line 119) — moot, whole tool removed by D-05.
  - Any remaining description strings in removed schemas that referenced `setup_mcp_admin` / `update_server_credentials` — moot, schemas deleted.
- **D-13 (sanity grep):** Final sweep — `grep -r "mcp_admin" src/ --include="*.py"` should return only legitimate hits: the directory name `~/.ssh/mcp/mcp_admin_key` (still generated, per Phase 33 D-09a), the `_SERVICE_NAMES` keyring namespace, and test-only references. Any production docstring / user-facing string that still calls out `mcp_admin` as "the" user gets reworded to a generic "your registered user" or deleted.

<code_context>
## Existing Code Insights

### Reusable Assets
- `CredentialNotFoundError` already exists and carries an actionable `credentials add <hostname> <username>` message — D-04 extends it with an ambiguous-match variant (or a new sibling exception class). No new error infrastructure needed.
- `resolve_ssh_credentials()` is a two-tier resolver post-Phase-33 — D-04 adds a registry scan step *inside* tier 2 (keyring), not a third tier. The contract stays two-tier: explicit args, then keyring (with registry-scan-by-hostname as the keyring sub-step when username is omitted).
- Phase 33 AST meta-test harness — D-08/D-09/D-10 extend the same file, same pattern.
- `credential_store.list_credentials()` — already enumerable via the JSON hostname registry (Phase 33 D-19 confirmed this for `list_registered_servers`). D-04's registry scan reuses this path.

### Established Patterns
- **Lock-step MCP tool deletion** (schema + handler + dispatch + annotation + openapi + underlying function) — Phase 33 did it for 4 tools (D-10, D-20, D-21). Phase 33.1 does it for 2 more.
- **Lazy keyring import** inside each function body — preserve in any new D-04 registry-scan code path.
- **Revert-proof regression tests** — every decision above must have at least one test that fails if the change is reverted. D-08/D-09/D-10/D-11 cover the meta-guards; positive coverage per-change is the planner's task breakdown.
- **Quality-gate schema/annotation parity** (CI enforced, v1.2) — will fail if D-05 lock-step is incomplete. Intentional safety net.

### Integration Points
- `resolve_ssh_credentials()` is the single funnel — extending D-04 behavior there propagates to every SSH-touching module automatically.
- `prompt_registry.py` — only `_build_connect_to_device_result` names a removed tool (D-05b). No other prompt needs rewriting.
- `tools/list` MCP response — will drop 2 tools. MCP client reconnect picks it up; no migration path needed.

</code_context>
