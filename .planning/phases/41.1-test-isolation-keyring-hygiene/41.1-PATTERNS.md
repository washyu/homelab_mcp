### `tests/test_sitemap.py:947-953` (test, unit) — MODIFY (single-line fix)

**Analog:** `tests/integration/test_credential_binding_round_trip.py:62-65` (dual-alias `_REGISTRY_PATH` monkeypatch).

**Current code** (lines 947-952):
```python
monkeypatch.setattr(
    "homelab_mcp.credential_store._REGISTRY_PATH", tmp_path / "registry.json"
)
from src.homelab_mcp.credential_store import register_credential

cred_id = register_credential("test-host", "test-user", credential_type="ssh")
```

**Bug:** patches the `homelab_mcp.credential_store` alias, then imports `register_credential` from `src.homelab_mcp.credential_store` — different module objects in `sys.modules`. The `register_credential` call writes to the REAL `~/.homelab_mcp/credential_registry.json`. This is a strong candidate for the `test-host`/`test-user` registry leak.

**Fix (apply dual-alias pattern):**
```python
registry_path = tmp_path / "registry.json"
monkeypatch.setattr("homelab_mcp.credential_store._REGISTRY_PATH", registry_path)
monkeypatch.setattr("src.homelab_mcp.credential_store._REGISTRY_PATH", registry_path)
```

Note this does NOT explain the keyring leak (`register_credential` writes ONLY to JSON registry, not keyring per RESEARCH Pitfall 2) — but it does explain registry pollution if the integration test ran first and primed the wrong module's `_REGISTRY_PATH` to a real path. The Wave-0 forensic task confirms which.

## Shared Patterns

### Dual-Alias Module Path Monkeypatching
**Source:** `tests/integration/test_credential_binding_round_trip.py:62-65`
**Apply to:** New session-autouse fixture in `tests/conftest.py`; the `test_sitemap.py:947` fix.
**Why:** Production code imports via `src.homelab_mcp.X`; package-relative imports go via `homelab_mcp.X`. Both names are distinct module objects in `sys.modules`. A single-alias patch is a silent leak.
```python
monkeypatch.setattr("src.homelab_mcp.credential_store._REGISTRY_PATH", registry_path)
monkeypatch.setattr("homelab_mcp.credential_store._REGISTRY_PATH", registry_path)
```

### `pytest.MonkeyPatch()` Constructor (session scope)
**Source:** RESEARCH §Pattern 1, verified live. **No prior art in this repo** — but documented Pytest 8 API.
**Apply to:** Session-autouse fixture only. The function-scoped `monkeypatch` fixture cannot be injected into a `scope="session"` fixture. Use:
```python

try:
    mp.setattr(...)
    yield
finally:
    mp.undo()
```
