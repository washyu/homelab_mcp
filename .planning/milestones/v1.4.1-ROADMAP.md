# Milestone v1.4.1: Security Patch

**Status:** ✅ SHIPPED 2026-04-01

## Overview

Patch release closing two critical security findings from the CodeRabbit PR #39 review: shell command injection via public key interpolation (SEC-01) and TOFU race condition allowing concurrent writes with different keys (SEC-02). Remaining 7 findings deferred to a future milestone.

## Phases

### Phase 30: Security Fixes

**Goal**: Close SEC-01 (shell injection) and SEC-02 (TOFU race condition)
**Depends on**: v1.4 baseline
**Plans**: 2 plans

Plans:

- [x] 30-01: TOFU lock scope fix (SEC-02) — widen `_tofu_lock` to cover entire check+store sequence
- [x] 30-02: Shell injection fix via SFTP tmpfile delivery (SEC-01) — eliminate f-string key interpolation

**Details:**

**Plan 30-01 (SEC-02):** Moved `_tofu_lock` acquisition from `_store_host_key` to `validate_host_public_key`, covering the entire TOCTOU window. Replaced `asyncio.Lock()` with `threading.Lock()` (sync callback context). Fixed `_store_host_key` to strip trailing comment field from key export. Added concurrency test proving single known_hosts entry after race.

**Plan 30-02 (SEC-01):** Replaced f-string shell interpolation of public keys with SFTP-based tmpfile delivery: key written to local tmpfile, uploaded via `conn.start_sftp_client()`, grep/cat read from remote tmpfile, cleanup in `finally` block. No key content ever touches a shell string.

## Milestone Summary

**Key Decisions:**

- `threading.Lock` (not `asyncio.Lock`) for `_tofu_lock` — `validate_host_public_key` is a synchronous callback invoked by asyncssh from thread context
- Caller-holds-lock pattern: `_store_host_key` is a dumb file writer; lock acquisition lives at `validate_host_public_key`
- SFTP-based key delivery: key content written to local tmpfile, uploaded via SFTP, never interpolated into shell strings
- `grep -Ff {remote_tmp}` replaces `grep -F "{public_key}"` — file-based pattern matching eliminates injection vector

**Issues Resolved:**

- SEC-01: Shell command injection via public key interpolation in `setup_remote_mcp_admin`
- SEC-02: TOFU race condition — concurrent first-connections could write conflicting keys

**Issues Deferred:**

- SSH-01: Keyring auto-injection disambiguation for multiple credentials per hostname
- SSH-02: Per-call timeout forwarding to `ssh_connect()` handshake
- SSH-03: `verify_mcp_admin_access()` not using resolved port/credentials
- ERR-01: `resolve_ssh_credentials()` unhandled exception path
- ERR-02: WebSocket PTY reader not closing on EOF/error
- QUAL-01: Proxmox `iso`/`cdrom` mutual exclusivity not enforced
- QUAL-02: `test_http_app.py` EOF test exercising local copy instead of production code

**Technical Debt Incurred:**

- None — clean security-only patch
