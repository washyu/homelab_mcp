1. Create an async helper function `_sudo_run` near the top of the module (after the `SSHCredentials` class, before `setup_remote_mcp_admin`). Signature:

```python
async def _sudo_run(
    conn: asyncssh.SSHClientConnection,
    command: str,
    password: str | None = None,
    check: bool = False,
) -> asyncssh.SSHCompletedProcess:
```

Implementation:
- If `password` is not None:
  - Run: `conn.run(f"sudo -S {command}", input=password + "\n", check=check)`
  - `sudo -S` reads the password from stdin. The `input` parameter of asyncssh's `conn.run` pipes data to stdin without shell echo, so the password never appears in `ps` output.
  - Catch the result. If exit_status != 0, inspect stderr for known patterns:
    - If stderr contains "incorrect password" or "Sorry, try again" -> raise a RuntimeError with message: f"sudo authentication failed: wrong password for current user. Verify the password stored in keyring for this host."
    - If stderr contains "not in the sudoers file" -> raise a RuntimeError with message: f"sudo authorization denied: current user is not in the sudoers file on the remote host."
    - Otherwise, return the result as-is (let caller handle non-sudo errors)
- If `password` is None:
  - Run: `conn.run(f"sudo {command}", check=check)`
  - This assumes NOPASSWD is configured. If it hangs, asyncssh's connection timeout will eventually fire.
- Return the SSHCompletedProcess result.

IMPORTANT: The `input` parameter value must include a trailing newline (`password + "\n"`) because sudo expects the password line to be terminated.

IMPORTANT: For commands that use pipes (e.g., `echo "..." | sudo tee ...`), these need special handling. The `_sudo_run` helper is for commands where `sudo` is the entry point. For piped commands like `echo "key" | sudo -u mcp_admin tee -a file`, restructure them to avoid the pipe:
- `echo "key" | sudo -u mcp_admin tee -a file` becomes `_sudo_run(conn, f'bash -c \'echo "{public_key}" >> /home/mcp_admin/.ssh/authorized_keys\'', password=creds.password)` or use `_sudo_run(conn, f"tee -a /home/mcp_admin/.ssh/authorized_keys", password=creds.password)` with `input` containing both password and content -- but this is tricky with sudo -S reading first line as password.

Actually, the simpler approach for piped-to-tee commands: use `_sudo_run` with a shell wrapper:
- `_sudo_run(conn, f'sh -c "echo \\"{public_key}\\" >> /home/mcp_admin/.ssh/authorized_keys"', password=creds.password)`
- Or keep the original pipe approach but use `_sudo_run` for the sudo part only.

The cleanest approach: For commands that pipe content INTO sudo, keep using `conn.run()` directly but modify the command to use `sudo -S` when password is available. Create a second helper `_sudo_cmd_prefix` that returns either `f"echo '{password}' | sudo -S"` -- NO, that's the insecure pattern.
