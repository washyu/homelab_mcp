<objective>
Create `credential_store.py` — the single module that wraps the OS keyring and exposes `store_credential`, `get_credential`, and `delete_credential` to the rest of v1.3. The critical invariant is that every function returns a safe value (`None` or `False`) rather than propagating any exception when the OS keyring is unavailable (headless Linux, no D-Bus session).

Purpose: Provides the building block that Phase 18 (CLI) and Phase 19 (auto-inject) depend on. Satisfies CRED-07: server warns and falls back gracefully to env-var-only mode when OS keyring is unavailable.

Output: `credential_store.py` (production), `tests/test_credential_store.py` (9 test cases, all green), `pyproject.toml` updated to promote `keyring>=25.6.0` to core dependencies.
</objective>

<feature>
  <name>credential_store — headless-safe OS keyring wrapper</name>
  <files>src/homelab_mcp/credential_store.py, tests/test_credential_store.py, pyproject.toml</files>
  <behavior>
    All behaviors are synchronous (no async) — keyring is a synchronous library.

    store_credential(hostname, username, password) -> bool:
    - Returns True when keyring.set_password succeeds
    - Returns False (with logger.warning) when NoKeyringError is raised
    - Returns False (with logger.warning) when RuntimeError is raised
    - Returns False (with logger.warning) when any other Exception is raised
    - Never propagates an exception to the caller

    get_credential(hostname, username) -> str | None:
    - Returns the password string when keyring.get_password succeeds and entry exists
    - Returns None when keyring.get_password succeeds but entry does not exist (keyring returns None)
    - Returns None (with logger.warning) when NoKeyringError is raised
    - Returns None (with logger.warning) when RuntimeError is raised
    - Returns None (with logger.warning) when any other Exception is raised
    - Never propagates an exception to the caller

    delete_credential(hostname, username) -> bool:
    - Returns True when keyring.delete_password succeeds
    - Returns False when PasswordDeleteError is raised (entry did not exist — treated as non-error)
    - Returns False (with logger.warning) when NoKeyringError is raised
    - Returns False (with logger.warning) when RuntimeError is raised
    - Returns False (with logger.warning) when any other Exception is raised
    - Never propagates an exception to the caller

    Key naming: keyring service_name = "homelab-mcp", keyring username = f"{username}@{hostname}"
    This allows multiple users per host (root@192.168.1.1 and admin@192.168.1.1 are separate entries).

    Module-level constraint: NO import of keyring at module level. Only `import logging` at top.
    All keyring imports must be inside function bodies with `# noqa: PLC0415`.

    No imports from homelab_mcp — this module must be self-contained (circular import prevention,
    mirrors the constraint on prompt_registry.py per STATE.md).
  </behavior>
