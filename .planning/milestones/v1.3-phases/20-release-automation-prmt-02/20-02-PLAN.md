    **Part B: Add publish-to-pypi job to main.yml**

    Append the following job after the existing `release:` job block (after line 212). Use exact indentation matching existing jobs (2-space indent for job name, 4-space for fields):

    ```yaml
      # PyPI publish - only on v* tags, only after tests pass (OIDC, no stored secrets)
      publish-to-pypi:
        name: Publish to PyPI
        runs-on: ubuntu-latest
        needs: [test-and-quality]
        if: startsWith(github.ref, 'refs/tags/v')
        environment:
          name: pypi
          url: https://pypi.org/p/homelab-mcp
        permissions:
          id-token: write

        steps:
        - uses: actions/checkout@v6

        - name: Install uv
          uses: astral-sh/setup-uv@v4
          with:
            enable-cache: true
            cache-dependency-glob: "pyproject.toml"

        - name: Set up Python
          run: uv python install 3.12

        - name: Build distributions
          run: uv build

        - name: Publish to PyPI
          uses: pypa/gh-action-pypi-publish@release/v1
    ```

    Key properties (per research):
    - `needs: [test-and-quality]` — CICD-03: publish blocked if tests fail
    - `if: startsWith(github.ref, 'refs/tags/v')` — CICD-01: only v* tags, not branch pushes
    - `permissions: id-token: write` at job level, NOT workflow level — CICD-02: OIDC, no secrets (Pitfall 3 from research)
    - `environment: name: pypi` — must match PyPI trusted publisher registration (Pitfall 2 from research)
    - `pypa/gh-action-pypi-publish@release/v1` — NOT @master (deprecated per research State of the Art)
    - Do NOT add `needs: [release]` — publish depends on test-and-quality directly (Anti-pattern from research)
    - Do NOT add `PYPI_API_TOKEN` to the job or workflow env — OIDC replaces it entirely (Anti-pattern)
