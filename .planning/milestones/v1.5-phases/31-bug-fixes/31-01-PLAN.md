**SSH-02 fix (test_ssh_tools.py, line 191):**
Remove the always-true `or "credentials add"` branch from the assertion. The current assertion is:

```python
assert "No credentials" in result_data["error"] or "credentials add" in result_data["error"]
```

The error message always contains `"credentials add"`, making the `or` branch trivially true and masking any failure of the `"No credentials"` check.

Replace line 191 with a single, non-disjunctive assertion:
```python
assert "No credentials" in result_data["error"]
```

This ensures the test will fail if the production error message no longer contains the `"No credentials"` string — which is the actual behavior being tested.

Note: The test also needs `list_credentials` and `get_credential` patched to return empty/None since the production code now calls `resolve_ssh_credentials` which uses keyring. Check whether the test currently passes without those patches. If the test already passes (because CI has no keyring entries), the assertion fix alone is sufficient.
