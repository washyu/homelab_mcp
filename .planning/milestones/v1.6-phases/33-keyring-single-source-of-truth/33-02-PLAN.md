| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-03 | Information Disclosure | Legacy DB rows dumped during backup → plaintext/weakly-encrypted passwords leaked | mitigate | D-01 DROP TABLE actively removes the rows on first startup. | T-33-04 | Denial of Service | Migration silently fails (e.g., locked DB) — server starts with stale credentials in DB + new keyring entries both live | accept | SQLite DROP TABLE is atomic; `DROP IF EXISTS` is idempotent. If first migration run fails, next startup retries. Consequence: brief desync window; user-observable via `credentials list` vs. tool behavior. Acceptable for single-user homelab per PROJECT.md |
| T-33-05 | Tampering | Postgres migration runs with insufficient privileges — DROP silently fails | accept | Not in deployment target (PROJECT.md A2: Postgres is effectively dead code). `DROP IF EXISTS` minimizes privilege requirement (vs. DROP without guard). Per-role DDL tuning is out of scope |
