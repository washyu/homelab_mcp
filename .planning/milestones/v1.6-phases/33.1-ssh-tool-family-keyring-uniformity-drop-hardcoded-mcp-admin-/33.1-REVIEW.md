## Warnings

### WR-01 — Shell injection via unescaped password in sudo fallback

**File:** `src/homelab_mcp/ssh_tools.py:454`
**Severity:** warning
**Introduced by 33.1:** no (pre-existing)

The password branch constructs `full_command = f"echo '{password}' | sudo -S {command}"` with raw interpolation. A password containing a single quote (`'`) or shell metacharacter breaks out of the quoted string and enables arbitrary command execution on the remote host under the authenticated user's privileges. The `# nosec B608` comment misclassifies the risk as SQL injection; the actual risk is shell injection via an already-authenticated credential.

**Fix options:**
```python
# Option 1 — asyncssh stdin (preferred)
proc = await conn.create_process(f"sudo -S {command}")
proc.stdin.write(f"{password}\n")
proc.stdin.write_eof()
result = await proc.wait()

# Option 2 — shlex.quote
import shlex
full_command = f"echo {shlex.quote(password)} | sudo -S {command}"
```

### WR-02 — ssh_execute_command auto-injects mcp_admin key; ssh_discover_system does not

**File:** `src/homelab_mcp/ssh_tools.py:482-485`
**Severity:** warning
**Introduced by 33.1:** no (pre-existing, deferred to 33.2)

When `creds.password` and `creds.key_path` are both empty and `creds.username == "mcp_admin"`, `ssh_execute_command` auto-injects the local `mcp_admin_rsa` key via `ensure_mcp_ssh_key()`. `ssh_discover_system` has no equivalent branch — it raises `ValueError` (lines 244-248) when no credentials resolve. The same hostname can therefore succeed under `ssh_execute_command` but fail under `ssh_discover_system` for a user named "mcp_admin" with no keyring entry.

Phase 33.1 deliberately deferred this surface to Phase 33.2 (see `DEFERRED_MCP_ADMIN_DEFAULT_FILES` in `tests/test_ast_regression.py`). **Advisory only**: the deferred state is documented, but the asymmetry is visible to agents calling both tools. Consider adding a docstring note on `ssh_execute_command` flagging the asymmetry until 33.2 lands.
