<objective>
Complete the field-loss fix (bug #1) at the database layer and close bug #2 (zombie sitemap rows on IP change). Both bugs require coordinated changes to `database.py` (writer + reader + schema) and `migration.py` (one-time startup step).

Five coordinated changes land in one plan because they share files and MUST ship atomically:
1. **D-01 / D-01a — hostname-only upsert, both adapters:** rewrite the `SELECT id FROM devices WHERE hostname = ? AND connection_ip = ?` match clause in `SQLiteAdapter.store_device` and `PostgreSQLAdapter.store_device`; branch on hostname-degenerate to preserve distinct error rows.
2. **D-09c — SQLite column adds + UPDATE/INSERT threading:** add `usb_devices TEXT`, `pci_devices TEXT`, `block_devices TEXT` to SQLite `init_schema`; thread the three columns through `SQLiteAdapter.store_device` UPDATE + INSERT + value tuples; add three JSON-decode branches to `SQLiteAdapter.get_all_devices`.
3. **D-09b Postgres option 1 (JSONB-extend, recommended per PATTERNS):** add the three keys to `PostgreSQLAdapter.store_device`'s `system_info` dict; mirror the flatten in `PostgreSQLAdapter.get_all_devices`. Zero schema change on Postgres.
4. **Stale-constraint addendum (planner-critical per CONTEXT addendum):** drop `UNIQUE(hostname, connection_ip)` + `idx_devices_hostname_ip` from both adapters via the migration step; add a non-unique `idx_devices_hostname` replacement.
5. **D-02 / D-02a — dedup migration + ALTER TABLE migration step:** one-time startup step in `migration.py` (both adapters) that collapses duplicate hostnames into a single row (merging non-null siblings), ALTER TABLEs in the three new SQLite columns, and drops the stale UNIQUE constraint + composite index.

Depends on Plan 02 because `NetworkDevice` must first carry `usb_devices` / `pci_devices` / `block_devices` attributes so `asdict(device)` produces those keys for this plan's writer extension to pick up via `device_data.get("usb_devices")`.

Purpose: Without this plan, the producer (Plan 01) and reader (Plan 02 parse) still write correct names into a `device_data` dict — but `SQLiteAdapter.store_device` never threads them into a column; the columns do not exist; the stale UNIQUE constraint still sits on `(hostname, connection_ip)` and a hostname-only UPDATE would leave duplicates.

Output: `database.py` with both-adapter hostname-only upsert and SQLite column threading; `migration.py` with a Phase 35 one-time block in BOTH migration functions.
