<objective>
Fix bugs #1 (field-loss at the producer) and #3 (tool hangs 4+ minutes at the per-subprocess level) inside `ssh_discover_system`. Align the producer to the sitemap-expected field names (D-09a) so `parse_discovery_output` actually lands CPU cores, memory breakdowns, and disk filesystem/size/use_percent/mount into the devices row. Wrap every probe `conn.run(...)` call with a 10-second per-command timeout (D-05). Emit `partial: true` + `timed_out_commands: [...]` only when any timeout fires (D-06, back-compat otherwise). Bump the outer `@ssh_connection_wrapper` timeout from 30.0 to 120.0 (D-08) so per-cmd timeouts remain the primary guardrail.

Purpose: The contract mismatch between `ssh_discover_system` (producer) and `sitemap.parse_discovery_output` (consumer) is the root cause of the "sitemap row has NULL cpu_cores, NULL memory_*, NULL disk_*" bug surfaced by Phase 33 live testing. Per D-09a, the downstream consumer dictates field names — the producer bends to match. Unbounded `conn.run()` calls are the root cause of the 4+ minute hang when any single probe command stalls.

**Pre-existing defect B1 (NEW — found by plan-checker):** `ssh_tools.py:266-428` (all probe blocks: CPU, memory, disk, network, uptime, os, lsusb, lspci, lsblk) is currently NESTED inside the `if hostname_result.exit_status == 0 and hostname_result.stdout:` branch at line 262. If the `hostname` probe returns None (timed out per D-05) or empty stdout, ALL subsequent probes are silently skipped — `system_info` ends up empty, but the function would return `{"status": "success", "partial": true, "timed_out_commands": ["hostname"], "data": {}}`. This defeats D-06 partial-mode semantics ("other probed fields still populate"). **Task 1 MUST dedent the probe blocks** so the `hostname`-success `if` guards ONLY the `actual_hostname = ...` assignment; every probe runs unconditionally at the function body level.

Output: `src/homelab_mcp/ssh_tools.py` with a new `_run_with_timeout` helper, rewritten `ssh_discover_system` body using that helper at every call site, aligned field names, **probe blocks dedented out of the hostname-success branch**, conditional partial-mode injection, and the decorator bumped to 120.0.

    ```python
    async def _run_with_timeout(
        conn: asyncssh.SSHClientConnection,
        command: str,
        *,
        cmd_name: str,
        timed_out: list[str],
        timeout: float = 10.0,
    ) -> "asyncssh.SSHCompletedProcess | None":
        """Run a discovery probe with a per-command timeout (Phase 35 D-05).

        Wraps ``asyncio.wait_for(conn.run(command, check=False), timeout=...)``.
        On :class:`TimeoutError`, logs at DEBUG, appends ``cmd_name`` to
        ``timed_out`` (D-06 accumulator), and returns ``None`` so the caller
        can leave the corresponding probed field unset — the final JSON lands
        a ``None`` at that position.
        """
        try:
            return await asyncio.wait_for(
                conn.run(command, check=False), timeout=timeout
            )
        except TimeoutError:
            logger.debug(
                "SSH discovery probe %r exceeded %.1fs on %s; field skipped",
                cmd_name, timeout, conn._host if hasattr(conn, "_host") else "?",
            )
            timed_out.append(cmd_name)
            return None
    ```
