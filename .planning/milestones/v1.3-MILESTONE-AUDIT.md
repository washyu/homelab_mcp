## E2E Flow Verification (4/4 Complete)

### Flow 1: Credential Store and Use — COMPLETE

1. `homelab-mcp credentials add myhost myuser` → `_cmd_credentials_add` calls `getpass.getpass`
2. `store_credential` writes to keyring → returns `True`; `register_credential` appends to JSON registry
3. SSH tool called with no credentials → `resolve_ssh_credentials("myhost")`
4. Tier 2: `list_credentials("ssh")` → hostname match → `get_credential` → password retrieved
5. `SSHCredentials(password=keyring_password)` returned → SSH connection succeeds

### Flow 2: Headless Fallback — COMPLETE

1. `store_credential` catches `NoKeyringError` → logs warning → returns `False`
2. `_cmd_credentials_add` detects `False` → prints warning to stderr → `sys.exit(1)`
3. `get_credential` returns `None` → Tier 2 in `resolve_ssh_credentials` does not enter `if keyring_password:` branch
4. Resolution falls through to DB lookup then default `mcp_admin` key path — no exception propagated

### Flow 3: Release — COMPLETE

1. `git tag v1.3.0 && git push origin v1.3.0` → `publish-to-pypi` `if:` condition satisfied
2. All `needs` jobs (`test-and-quality`, `cross-platform`, `security`, `release`) run and pass
3. `uv build` produces wheel from `pyproject.toml` at version `1.3.0`
4. `pypa/gh-action-pypi-publish` exchanges GitHub OIDC token for PyPI upload — no stored secrets

### Flow 4: Decommission Prompt — COMPLETE

1. AI receives `decommission_device_workflow` prompt via MCP `get_prompt`
2. `_build_decommission_result(args)` renders: step 1 calls `get_network_sitemap`, extracts `device_id` (integer)
3. Steps 2 and 4 use `device_id=<device_id from step 1>` — integer, not hostname string
4. `decommission_device` called with integer `device_id` → no JSON schema validation error
