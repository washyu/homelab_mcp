# Milestone v1.6: Credential Architecture Cleanup

**Status:** ✅ SHIPPED 2026-04-24
**Phases:** 33, 33.1 (INSERTED), 34, 35 (INSERTED)
**Total Plans:** 18 (5 in Phase 33 + 5 in Phase 33.1 + 4 in Phase 34 + 4 in Phase 35)

## Overview

Make the OS keyring the **single source of truth** for remote credentials. Drop the parallel DB `ssh_credentials` table, remove all `mcp_admin` hardcoded defaults on the credential path, delete the `setup_mcp_admin` MCP tool, fix the `register_server` verify-bypass, and add cluster-scoped Proxmox API tokens so one credential serves all nodes in a datacenter. Two scope-expansion phases (33.1 SSH Tool Family Keyring Uniformity and 35 Sitemap + Discovery Reliability) were inserted mid-milestone, surfaced by Phase 33 live testing 2026-04-21.

## Milestone Summary

**Decimal/Inserted Phases:**
- **Phase 33.1**: SSH Tool Family Keyring Uniformity (inserted after Phase 33 to close gaps from live testing — schema cleanup, lock-step tool deletes, sitemap default removal)
- **Phase 35**: Sitemap + Discovery Reliability (inserted after Phase 34 to close field-loss / zombie rows / SSH timeout / null-threshold bugs surfaced by live testing)

**Key Decisions:**

- *Keyring single source of truth* — no parallel DB credential storage; users with credentials in the dropped `ssh_credentials` table re-add via `credentials add` (no auto-migration; single-user homelab scope)
- *Two-tier `resolve_ssh_credentials`* — Tier 1: explicit args; Tier 2: keyring (registry username scan when no username given). No mcp_admin fallback; raise `CredentialNotFoundError` with actionable `credentials add <host>` pointer on miss
- *`register_server` verify-only* — schema reduced to hostname/username/port/display_name; no password / key_path / verify_connection params; call goes through `resolve_ssh_credentials` then `asyncssh.connect`. No code path accepts a registration without verified credentials
- *Lock-step tool deletion* — when removing an MCP tool, schema + handler + dispatch + annotation list + annotation dict + openapi allowlist + openapi category all updated together (7-way parity, was 5-way before 33.1). Import-time parity assertion catches both list and dict shapes
- *Cluster-scope keyring key form* — `{username}@cluster:{cluster_name}` (not a separate service name) — cluster credentials live in the same keyring service as per-node, distinguished by the `@cluster:` token in the username slot
- *Async `get_proxmox_client`* — resolver became async; INJECT-03 "first registry entry" shortcut deleted entirely; 9 internal call sites updated to `await get_proxmox_client(host=host, session=session)`
- *`_HOST_CLUSTER_CACHE` plain dict* — not `functools.lru_cache` (allows `.clear()` in test fixtures); short-circuits second resolution when host already known
- *Hostname-only upsert with degenerate-hostname fallback* — `None` / `""` / `'unknown'` fall back to `(hostname, connection_ip)` match; preserves Phase-33 distinct-error rows; `connection_ip` moved to UPDATE SET so re-discovery with new IP overwrites instead of creating duplicates
- *SQLite rebuild pattern for stale UNIQUE drop* — DROP INDEX + DROP TABLE IF EXISTS devices_new (orphan recovery) + CREATE + dynamic column-copy INSERT + DROP + RENAME + CREATE INDEX. Migration uses dynamic `PRAGMA table_info` (not literal column list — survives schema drift)
- *JSONB-extend for Postgres new fields* — usb/pci/block land inside existing system_info JSONB through `_maybe_json_load` helper; flattened back to top-level keys in `get_all_devices` for reader symmetry with SQLite
- *Per-subprocess SSH timeout* — `_run_with_timeout(timeout=10.0)` wraps every `conn.run` probe in `ssh_discover_system`; `@ssh_connection_wrapper(timeout_seconds=120.0)` bumped from 90s to cover full discovery wall-time. Timeouts append to `timed_out_commands`; payload tagged `partial: True`
- *Parallel bulk discovery* — `bulk_discover_and_store` uses `Semaphore(10)` + `asyncio.gather` so 10 hosts probe concurrently; previously serial (4+ minute hangs reduced to 30-40s for a 10-host fleet)
- *Null-threshold defensiveness* — `_has_threshold_data` helper in `sitemap.py` analyzers; `device.get("cpu_cores") or 0` style coercion banned (AST meta-test D-16); analyzers skip devices with null fields instead of returning false-positive deployment recommendations
- *AST meta-tests as regression guards* — class of bugs (always-passing ternaries, missing `await`, wrong upsert key, threshold coercion) that no single positive regression test can catch — parse production source AST and walk for forbidden patterns. Phase 33.1 D-08 + Phase 35 D-14/D-15/D-16 are the v1.6 examples
- *Audit verdict `passed`* — 5/5 requirements satisfied across 7/7 wiring checks and 4/4 E2E flows; tech debt non-blocking (Nyquist VALIDATION.md gaps, downstream mcp_admin defaults in non-resolver code paths)
